# The PDF backends the CORPUS INTAKE path needs, and nothing else needs.
#
#     python3 -m pip install -r requirements-lock.txt -r requirements-intake.txt
#     sudo apt-get install -y poppler-utils
#
# Kept apart from `requirements-lock.txt` on purpose. The readers, the grid
# engine and the finalizer never open a PDF - they are given rasters - so a
# machine that only digitizes figures does not need any of this, and a lock
# file that demanded it would make the core install larger than the core work.
#
# THE SPLIT IS ALSO WHY THE SCENARIO COUNT HAS TWO VALUES. `test_corpus_intake`
# SKIPs its adapter, per-status, renderer and crop sections where no backend is
# installed: 111 scenarios without, 149 with - a difference this file is the
# cause of, and the only number it is entitled to state. What the WHOLE package
# runs under each profile is in the `CURRENT_SCENARIO_COUNT_CORE` and
# `CURRENT_SCENARIO_COUNT_FULL` markers in `README.md`, measured every CI run;
# it was copied here as well and went stale for eleven releases, which is what
# a second copy of a moving number does.
#
# poppler-utils is not a Python package and cannot be pinned here. The
# `intake-full` job records `pdftotext -v` in its log, so a runner image that
# changes it is visible rather than mysterious - and the count is gated on
# poppler being PRESENT, which the job installs explicitly rather than
# inheriting from whatever `ubuntu-latest` happens to ship.

pypdf==3.17.4
